How Intermission works

The show is planned in files, played by one small program, and previewed in a model of the room. This page is the map — read it when it has been a few weeks and nothing looks familiar.

The host — one click

Double-click Intermission.command. The editors start and the Host page opens (the first tab on every page). Everything else is a click there:

What it does
ProjectSave, Save as, New, Load. A project is a folder in projects/ with the plan files — timeline, rig, looks, lanes and targets, the Library list — and which Live set, Resolume composition, TouchDesigner set and Advanced Output preset go with it. The TouchDesigner set lives in the show folder's td/ (default td/liveset/liveset.toe), so Dropbox shares it like the rest of the show; the timeline's TD lane switches its scenes and takes its stills over OSC. Loading first copies what's here to projects/.autosave/, and every open editor reloads, so nothing old is saved over what came in. New keeps the rig, lanes, looks and Library, and starts the timeline empty.
▶ TestOpens Resolume (with the project's composition), TouchDesigner (with its set, unless one is open already) and the set in Live, starts the Blender previz, the screen feed and the player.
● The showRuns the check first, then Resolume, Live, TouchDesigner and the player only — it follows Live, never the timeline — stops Blender and the feed, and keeps the Mac awake.
PANIC / ResumeThe same as p and r in the player's window.
  • Each part also starts and stops on its own, with its status and log (What happened). A crashed player is restarted in a second.
  • Resolume and Live are opened, never quit, from here: they hold the show. Arena opens as 7.19 (the licence); Live as the release that has AbletonOSC set up, not the beta (LIVE_APP=… picks another).
  • With the editors shared (./Intermission.command --lan) the other laptop can save and load projects, but only this Mac starts and stops software.

Test.command and Live.command below still work as they always did.

Two modes

There are only two things to start, and each is one double-click. Open Resolume and the show set in Live yourself, first; the launcher does the rest and tells you, before anything runs, what is missing.

Test — at home

Test.command

Blender previz✓
Syphon bridge (screen into Blender)✓
editors (these pages)✓
cue_player, following Live✓

Resolume's Lumiverse sends Art-Net to 127.0.0.1, so Blender's pars are the rig. Quit Blender or ctrl-C and it all stops.

./Test.command --plan — only the editors, for planning with no Resolume or Blender (your brother's usual).

Live — show night

Live.command

Blender previz—
Syphon bridge—
editors—
cue_player, following Live✓

Resolume's Lumiverse sends Art-Net to the venue's node. Only the player runs, the Mac is kept awake, and nothing can edit the plan. It checks strictly and asks before starting if anything is wrong.

Both run python3 preflight.py first — you can run it on its own any time. It checks that the plan maps, that Resolume answers and holds every clip the plan fires, and that Live answers with the tempo you expect.

Both launchers stop anything left over from an earlier run first, so a forgotten player can't hold the port. Test reuses a previz that is already open instead of starting a second Blender.

The status dots

The top bar of every page shows Resolume · Live · Player · Blender · Art-Net · Screen. Green is fine, amber is fine but worth a look (Live stopped), red is broken, grey is unknown. Hover a dot for what it's doing and how to fix it.

Panic, and crashes

In the player's window (the terminal the launcher opened):

  • p — panic. Sends the safe look from the "panic" block in osc_map.json (a cue value per lane, e.g. "lights": "Amber wash") and holds: no cues, no automation. Lanes it doesn't name stay where they are. The Player dot turns into a red PANIC.
  • r — resume. Back on the plan exactly where the music is, as if you had jumped there.

In Live mode, if the player dies it's restarted within a second and picks up where the music is. A panic survives that restart: it keeps holding until you press r.

Who talks to who

The rule that holds it together: Resolume is the only thing that drives the rig. Blender watches the same Art-Net and the same Syphon feed the real fixtures get, so the previz shows what the room will really do — never a separate guess.

One shortcut to that rule: while you are designing a look in the floor plan, the editor sends it straight to Blender, so you can build looks with Resolume closed. The moment real DMX arrives, it takes over.

The show composition

One layer per job, the same three as the timeline's lanes. A lane then switches inside one layer, so Resolume crossfades it and the layer's own effects, blend mode and automation stay on whatever plays there.

  2. Name the layers as above. The tools go by the numbers in osc_map.json → lanes; the names are for you.
  3. Move the picture up and the lights down. Clips fit to the width and sit in the middle, so with the layer's Transform: Screen A and B up 60 px, Lights down 540 px. Check it in the composition preview once.
  4. Columns are scenes, if you use them: name them, the Scenes lane fires them by name. They fire every layer at once.

  7. Save it, and play identify to check the patch.

Driving the pars

Resolume drives DMX by sampling pixels, so the pars need pixels of their own. They do not need video: a Solid Color layer whose opacity you automate is a fade. Video is for movement.

The control band

Make the composition taller than the beamer output — 1920x1200 with the projector mapped to the top 1920x1080 — and keep the bottom 1920x120 for the lights. Nobody sees it. If your Lumiverse's Input Source can be set to a layer or group instead of the whole composition, use that instead: same idea, nothing to project by accident.

Fixtures sit left to right in patch order. A par gets one unit and samples its middle; a pixel bar gets two units and samples each of its 18 pixels across its cell. With 8 pars and 4 bars that's 16 units of 120 px. band.py is the one place this is defined, and the loops and looks follow it. Print it for patching the Lumiverse:

python3 band.py

PAR_01 … PAR_08   one par each 120 px: samples x 60, 180, 300 … 900
BAR_01            cell  960-1200   18 pixels, x 967 → 1193
BAR_02            cell 1200-1440   18 pixels, x 1207 → 1433
BAR_03            cell 1440-1680   18 pixels, x 1447 → 1673
BAR_04            cell 1680-1920   18 pixels, x 1687 → 1913
The band used to be 6 cells of 320 px. If your Lumiverse was patched to that, move the fixtures to these points once.

The presets

uv run make_light_loops.py makes 38 presets in nine categories — Wash, Sweep, Chase, Rhythm, Strobe, Build, Colour, Bars, Utility (--list prints them). Each comes twice from the same frames: an .mp4 for the previews here, and a DXV .mov for Resolume — Arena held H.264 loops on their first frame under BPM Sync. They are made in stage space: each is a function of where a fixture really stands in rig.json, so a sweep crosses the stage, rotate goes around you, sweep-out starts nearest you, and a pixel bar shows a sweep passing through it pixel by pixel. Move fixtures and run it again to follow. Each preset gets a pattern card — the fixtures left to right, time running down — so a chase reads as a diagonal and a strobe as stripes.

In the floor plan's Loop mode, the preset button opens the browser: categories on the left, cards on the right, a search box. Hover a card and the plan and the 3D view play it; leave and the previous one comes back; click to keep it. ←→↑↓ preview as you move, enter keeps, esc closes.

Installing them in Resolume

To fire a preset from the timeline it has to be a clip in Resolume's lights layer. The browser's header says how many are (12 of 38 in Layer 3):

  • Install in Resolume loads every preset that isn't there yet, BPM-synced, with no beat snap. When the layer runs out of slots, columns are added at the end of the composition, so your scenes don't move.
  • ＋ on a card installs just that one; ✓ means it's there.
  • Once all are in, the button becomes Update in Resolume: it reloads every preset from disk into the same slots, for after re-rendering them.

From the command line: python3 -c "import arena_load; print(arena_load.install('http://127.0.0.1:8080'))".

Looks as clips

A look designed in the floor plan is a colour per fixture. Make clip (in the floor plan's Looks panel, or on a Lights cue whose look isn't a clip yet) renders it onto the band as a still — each fixture's whole cell in its colour — saves it to content/light-looks/ and loads it into the lights layer, named after the look. A Lights cue that names the look then fires it. Picking a look in the timeline's quick picker does this for you. Change a look? Make it again: it reloads into the same slot.

The loops are white on black so the colour comes from underneath: one loop serves every mood. They are written at the tempo in show.json and loop cleanly, so Resolume can resync them to the composition tempo.

Check the patch with it

Play identify.mp4: the fixtures light one at a time — the eight pars, then the four bars — in patch order. Watch the previz or the real rig. If the order is wrong, the fixtures are in the wrong cells — not the pars.

Two traps. A master fade pulls the lights down with the picture when the fixtures sample the whole composition — fade the projector's layer or group instead. And pixel values map straight to DMX, so the bottom of a fade gets chunky: give the automation target a positive curve so more of the fade happens where the pars actually respond.

Loading the clips

The media does not have to be dragged in by hand. With Arena's web server on (Preferences → Webserver → Enable Webserver & REST API, port 8080), arena_load.py fills a layer's clip slots from a folder and writes what it did into osc_map.json:

python3 arena_load.py --list                      # layers and what is in them
python3 arena_load.py --layer "LIGHTS" --dir content/light-loops --lane lights
python3 arena_load.py --layer 4 --dir content/screen --lane screen --dry-run

After that a Lights cue that says chase simply fires the chase clip: the loader put the file in a slot and told the map where it is. The timeline's What box offers the names it knows, and tells you which layer and clip a cue will fire — or says the name is not mapped yet.

Re-run it whenever the files change, after regenerating the loops at a new tempo say. It uses the same slots, so the cues stay valid.

Loading a clip from the timeline

Select a cue and use Load clip in the sidebar: it lists the files in that lane's folder, and picking one loads it into the lane's Resolume layer, maps it, and points the cue at it. One gesture instead of four.

Which layer and folder each lane uses is the lanes block in osc_map.json:

"lanes": {
  "lights": {"layer": 3, "dir": "content/light-loops"},
  "screen": {"layer": 1, "dir": "content/screen"}
}

A file already in the layer keeps its slot, so re-loading never scatters your clips. The sidebar then shows → Resolume layer 3, clip 6 under the cue, which is the quickest way to see a cue is wired up.

How it stays in time

Two different things, worth keeping apart:

  • When a clip starts — the cue fires at its bar, because the player follows Live's playhead. Installed clips have no beat snap: a snap would hold each one until Arena's own next bar, and a cue fired on Live's downbeat landed 1.4 s late with one.
  • How it runs — loaded clips are set to BPM Sync, so playback follows Arena's tempo. Turn on Ableton Link in Arena and that tempo follows Live, so a 2-bar chase stays in time even when the tempo changes. --no-sync leaves the transport alone.
Patching stays manual. The Lumiverse and its fixtures live in Advanced Output, which the API does not reach. Patch once, save the composition, and check the order by playing identify.mp4.

Conventions

Locators in Live

This is the contract between the music and the visuals.

## 1 · before       bar 1     a locator starting with ## names a chapter: a group of songs
>> Intermission     bar 2     a locator starting with >> starts a song
Build 1             bar 17    plain names are its sections
Drop 1              bar 33
>> Afterglow        bar 129   next song
  • Live allows one locator per position, so a song marker and its first section cannot share a bar. The gap is called Start automatically.
  • A chapter is a label over the songs that follow it — shown above the song row, in the strip above the timeline and in the setlist. No cue anchors to it. Put it a bar before its first >>.
  • Rename a section and every cue pointing at it is orphaned — on purpose, so renaming is a decision, not an accident.
  • Rewrite the music inside a section as much as you like. The plan holds.

Names

  • Looks are named things — "Amber wash", "White snap". A Lights cue names a look; it never describes a colour.
  • Screen and Lights cues name a clip exactly as Resolume calls it. The player finds it by name in the open composition, in the lane's layer. Move a clip to another slot and its cues follow; rename it and they turn ✗.
  • Scenes are Resolume columns, by name. Name a column in Resolume ("Drop 1") and that is the scene.
  • Bounces are dated: Set_2026-09-21.mp3.
  • Fixtures are PAR_01 … in the order they sit on the floor, stage right to stage left.

Time

Cues are stored as section + offset in bars. Never seconds. That single choice is what lets the music change without breaking the plan.

The Library

The Library tab gathers every visual into one list, so painting never means hunting through folders. Three views:

  • Sources — everything in the folders this Mac looks in (set them on the page: Add folder… on the right; they're yours alone, in sources.json next to the tools, so your render folders don't show up as his): videos, image sequences (a folder of numbered frames is one clip) and stills, grouped by project. Drafts, previews and render passes (depth, EXR) are hidden until you tick drafts. Hover a card and it plays.
  • In the show — what you've added: a name, a song, tags, who added it. Screen A / Screen B install it into that screen layer in Resolume; after that the timeline offers it.
  • Live — sources Resolume can see from outside it: TouchDesigner over Syphon, NDI. Add one and it's in the show like a clip, named your way.

Add to the show converts a copy into the show folder's library/: 1920×1080, at the frame rate it was made at, fitted (black sides) or filled (cropped) — the portrait renders need that choice — in a codec Resolume decodes on the GPU. The original stays where it is.

What it isBecomes
video or image sequenceDXV — roughly 9 MB per second
stillDXV, one frame
anything really transparentProRes 4444 (video) or PNG (still): ffmpeg's DXV has no alpha. For a lighter file, convert it in Resolume's Alley to DXV with alpha.

"Really" means some pixel isn't opaque: renders often carry an alpha channel that is full everywhere, and those go to DXV. The codec shows on each clip. python3 library.py --reconvert converts clips added before this again from their sources, under the same names; Install with the clip in a layer reloads it there.

library.json is the list and library/ the media — gigabytes. Both live in the show folder, shared through Dropbox; neither is in git.

From the Library into the timeline

  1. Add to the show in the Library (Sources → pick → Add).
  2. In the timeline, double-click the Screen A or Screen B lane where it should start. The quick picker lists the clips already in that layer, and then the Library's, marked in the Library. Pick one: it's installed into that layer and becomes the cue in one go.

Or install ahead of time from the Library (Screen A / Screen B, or Install all) and drag from the timeline's Resolume panel. The Library has a card view and a sortable list view (☰).

Two screen layers

The timeline has Screen A (layer 1) and Screen B (layer 2): a base and something to blend over it. Both lanes clear at the end of a cue by default, like Screen always did. Blend Screen B however you like in Resolume (Add, Screen, a mask); the timeline decides what plays when.

TouchDesigner: baked or live

  • Baked — render it and it goes through Sources like any video. Nothing can go wrong with it on the night.
  • Live — a Syphon Spout Out TOP in TD publishes it; Resolume lists it as a source; add it in Live and install it in a screen layer. Several TD scenes: one Syphon out each, or one out switched by the timeline's TD lane over OSC.

The Resolume panel

Under the timeline is your composition as Arena shows it: columns along the top, layers as rows of thumbnails, the top layer on top. Each layer says which lane uses it (→ lights). It follows Arena live, so a clip you load or move there shows here within a second.

  • Drag a clip onto a lane — a cue for that clip, at that bar.
  • Drag a column onto Scenes — a scene cue that fires the whole row.
  • Drag onto a cue — swaps its clip, keeping where and how long.
  • Click a clip — selects every cue that uses it. The yellow badge says how many.
  • A clip playing in Resolume has a green edge.

A cue on a lane whose layer isn't the clip's (a lights-layer clip on Screen) remembers its layer; the sidebar's Layer field shows and changes it.

Playing from the timeline: Drive

Normally the player follows Live's playhead. Turn on Drive next to the timeline's ▶ and it follows the timeline instead: play the bounce and every cue, fade and automation lane fires in Resolume, and the previz shows it — no Live needed. Scrubbing while paused jumps there too.

  • The browser still never talks to Resolume. It tells the player where it is; the player does the firing.
  • Live wins: the moment Live's playhead moves, the player follows Live again. A Live that is stopped doesn't pull the show back.
  • Live.command ignores the timeline completely (--live-only): on show night only Live drives.

When a cue ends

A cue's length is real. When it runs out and nothing on its lane takes over, the player clears the layers it played on — the screen goes empty rather than holding a clip the plan says is over. That's the default for Screen, Lights and TD; Scenes hold. At the end in the Cue tab changes it per cue: hold the last frame keeps it (the cue shows a striped right edge).

Jumping around works the same way: land anywhere and every layer the plan uses shows what the plan says there, including nothing.

Fades

Every clip on Screen A, Screen B and Lights fades in and out by itself, with easing — nothing to draw. How depends on its neighbours:

Where the clip isWhat happens
right after a clip in the same layera real crossfade: Resolume's layer transition, on its own clock
into an empty layerits own opacity eases up from 0
with nothing after itits opacity eases down to its end, then the layer clears
followed by a clip from another layerit fades out while that one fades in, and is cleared after
  • Defaults per lane, in bars, and the easing (smooth, straight, ease in, ease out): Show tab → Fades. Screen A/B start at 1 bar in and out, Lights at ½.
  • Per clip: drag the ▾ on its top edge (fade in, from the left) or the one near its right end (fade out); or in/out in the quick picker; or the Cue tab's fields. auto (an empty field) is the lane's default, cut is none. A faded-by-default part is drawn lighter than one you set.
  • The clip's opacity multiplies with its envelope (◠), the layer's and the composition's automation. After the cue it's put back to 100%.
  • Jumping around the arrangement, and panic, always cut.
  • A crossfade is at most 10 s (5 bars at 120 bpm), Resolume's longest transition. It uses the layer's blend mode: leave it on Alpha.
  • Other lanes (Scenes, TD) keep a plain fade in, as Resolume's transition.

Working fast: the quick picker

What a cue fires, how it fades and its note, set on the cue itself:

  • Double-click a lane — adds a cue and opens the picker on it. Type a few letters, enter. That's a whole cue.
  • Enter on a selected cue, or its ▾ button, opens the picker again.
  • It lists the clips in that cue's layer with thumbnails (columns, for Scenes; looks too, for Lights). ↑↓ and enter; a name that isn't there is used as typed.
  • With several cues selected, the picker and fade chips change them all.

The sidebar stays for the rest: song, section and offset (which dragging already sets), the layer, loading media files.

Arena closed? The panel and the player fall back to composition.json, the composition as last seen, so planning still works and your brother sees the same names. With no composition known at all, the player uses the positions in osc_map.json.

Cues and automation

The timeline has two kinds of lane, both anchored to sections in bars.

Cue lanes — things that happen

  • Scenes — a Resolume column, by its name (or a number): one trigger changes a whole row.
  • Screen — a clip, by name, in the screen layer.
  • Lights — a control-band clip, by name. A look from the floor plan shows in the previz but isn't a Resolume clip until one is made of it.
  • TD — a TouchDesigner scene.
  • Notes — for people, never sent.

Automation lanes — things that move

  • One OSC target per lane, picked from the library.
  • Double-click to add a point, drag to move it, double-click to remove it.
  • Each point either ramps to the next or holds until it.
  • Sent only when the value moves, so a flat stretch costs nothing.

Shaping automation

Points anchor to sections like cues. What happens between two points is the first point's shape:

ShapeDoesHow
straighta steady rampthe default
ease in / ease outslow then fast / fast then slowalt-drag the line up or down to bend it any amount, or pick it in To the next
S-curveeases both ends; alt-drag makes it steeperTo the next
holdstays, then jumps at the next pointTo the next

The timeline draws exactly what the player sends — they share one formula.

  • ∿ in a lane's header draws a shape over a stretch: sine (breathing), triangle, saw up (builds), saw down, square (on/off) or random (drifting), every N bars, between two levels. It works on your selected points' stretch, or the section under the playhead, and replaces the points there. The result is ordinary points, so you can still edit them by hand.
  • ⌘-drag in a lane draws freehand; it's thinned to the few points that keep its shape.
  • shift-drag a point changes only its value, five times finer.
  • While dragging, the value shows by the cursor — in % and in the target's own units.
  • ⌘C / ⌘V copy points and paste them at the playhead, in the same lanes.

Three levels: main, layer, clip

They multiply, like Resolume's own faders do:

LevelWhereChanges
Mainthe Main row at the top, ＋ automationthe whole composition: master, opacity, its effects. It dims the screen and the lights — the band is part of the composition.
Layer＋ next to a lane's name; its lanes sit right under itthat layer: opacity, master, every effect on it. On Lights: the dimmer for the whole rig, and colour through the Colorize (how much) and Hue Rotate (which) effects on layer 3.

The picker shows what's set up already for that level first, then everything else Resolume has there. The Transforms that place the band — the Lights layer's and the composition's — aren't offered: moving them would move what the fixtures read.

Automating Resolume parameters

The ＋ buttons and a lane's menu (＋ a Resolume parameter…) list the parameters in the open composition that can move: the master, composition and layer opacity, and every parameter of every effect (Lights · Colorize · Opacity). Type any words to find one.

  • It's stored by its name — layer, effect, parameter — not by an id, so it survives Arena restarting. The player sends it over the REST API at ~60 per second (about 0.2 ms each); an effect goes by its place in the layer's list, the only way Arena 7.19 takes it.
  • The button next to the lane's value (80…150) sets what 0% and 100% mean in the parameter's own units. It starts at the full range, which is often too wide: Scale goes to 1000, where 100 is normal size.
  • Two effects with the same name on one layer are Blur and Blur #2. Rename or reorder effects in Resolume and the lane turns up as missing in preflight.py; pick it again.

The address library

osc_map.json holds every target once, the way Ableton's OSC Send device does — so it travels with the project instead of being rebuilt in every Live set:

"targets": [
  {"name": "Master intensity", "address": "/composition/video/opacity",
   "min": 0, "max": 1, "curve": 0},
  {"name": "TD energy", "address": "/td/energy", "min": 0, "max": 1,
   "curve": 0, "port": 9000}
]

A Resolume parameter picked from the menu is saved there too, as {"name": "Layer 3 · Transform · Scale", "resolume": ["layer", 3, "effect", "Transform", "Scale"], "min": 80, "max": 150}. Raw OSC targets (for TouchDesigner, or anything else) are written by hand as above.

  • min / max — what 0% and 100% on the lane become.
  • curve — −1 to 1, for the whole target. Leave it at 0 and shape the lanes instead; use it only to correct a response, like pars that barely change in their bottom quarter.
  • host / port — optional; default is Resolume from the top of the file.
The hand-written OSC targets in there now are placeholders. For Resolume, pick real parameters from the lane menu instead; keep OSC for TouchDesigner.

On the night

cue_player.py --follow is the engine: it follows Live, fires the cues and plays the curves. Press Follow Live in the timeline and it becomes a mirror — the playhead follows the player, each lane shows the value being sent, and cues glow as they fire. The browser watches; it never sends.

Automation follows Live about 60 times a second: smooth for fades and builds, not beat-accurate. For anything locked to the beat, use Resolume's own BPM-synced effects over Ableton Link, and automate how much.

Working alone

A music session (Sil)

  1. Write. Keep locators up to date as the arrangement changes.
  2. Bounce the whole arrangement to audio/, dated.
  3. Re-sync the structure: 
    python3 sync_show.py --als-dir ~/Music
  4. Read the diff it prints. It names what moved and what is now orphaned.

A visual session

  1. Double-click Test.command.
  2. Floor plan for where the pars stand and what the looks are.
  3. Show timeline to place cues against the music you can hear.
  4. Check it in Blender, which lights the room with the look you are on.
  5. Before stopping: python3 cue_player.py --dry-run to see the whole show as a cue list, and catch anything that maps to nothing.

Working together

In the same room: Test.command asks Share the editors on this network? — say yes and it prints an address like http://192.168.1.126:8765/. The other laptop opens that: same plan, same Resolume, same previz, no copies. One person curates the Library while the other paints; the save guard stops you overwriting each other. Anyone on that network can edit while it's shared, so say no on a public network.

Apart: the code is the git repo; the show is one folder in Dropbox, Intermission Show, shared between you — the plan files, the Library's media, the bounces, Arena's composition names, the saved projects. Each Mac clones the repo and, the first time a launcher runs, says where the show folder is (showfolder.py). Add in the Library copies a clip, converted, into that folder; your own render folders stay where they are.

  • Hand-off is a bounce plus a sync. After a writing session, the new mp3 and the refreshed show.json are all the other side needs.
  • Don't both edit the same file at once. The editors save whole files, so two people editing cues.json at the same time will make a conflicted copy in Dropbox. One plans while the other writes.
  • An editor refuses to save over a file that changed since it loaded it, and says changed elsewhere — reload. That protects you from a forgotten tab wiping out newer work; reload the page and carry on.
  • Only the previz needs Blender. Planning needs the browser and the bounce.
  • Set the show folder to “Make available offline” in Dropbox, on both Macs: Resolume must never meet a placeholder file mid-show.
  • Don't put the repo itself in Dropbox. Git and a sync client fight over .git/; .live/ stays with the code and is never synced.

Show day

  1. Tape the floor from the plan: patch/floorplan.svg has distances and angles from where you sit; patch/patch.md has the addresses.
  2. Patch the pars, then check each one from Resolume before trusting anything.
  3. Point Resolume's Art-Net at the real node instead of 127.0.0.1.
  4. Open Resolume with the show composition and the set in Live.
  5. Double-click Live.command. Fix whatever it marks ✗, tick the checklist it prints, press Enter, and play the set.
Wi-Fi is not for DMX. Fine at home, cabled Ethernet on the day.

Arena 7.19.2 (the licensed version)

The show runs on Arena 7.19.2. Newer versions run as a demo there, with a watermark. python3 arena_check.py tries every Resolume call the tools use against whatever Arena is open, and cleans up after itself. On 7.19 it all works, with one exception, and the tools handle the rest by themselves:

  • Live sources (TouchDesigner over Syphon) can't be loaded by the API: drag the source into a slot in Arena once, select that clip, and press Name the selected Arena clip on the live entry in the Library.
  • 7.19 has no parameter-by-id: automation sets Resolume parameters through their layer or the composition instead — automatically.
  • 7.19 ignores a request that changes several clip settings at once, and drops quick successive ones on a clip that's loading: names and BPM Sync are set one by one and checked.

A composition saved in a newer Arena may not open in 7.19: build the show composition in 7.19.

When something is wrong

What you seeWhy
Blender shows 0 Art-Net packetsResolume holds the port too. It binds every local address, so this is rare — if it happens, bind Resolume's Art-Net node to one interface.
Screen stays on the test cardThe bridge isn't running, or Resolume has no Syphon output device. uv run syphon_bridge.py --list shows what is being published.
Cues in the timeline are redTheir section was renamed or deleted in Live. The sidebar re-points them in one click.
A cue does nothing when playedIt's striped with ✗: the name isn't in the open composition. Fold the lane open to see why. --dry-run lists them all.
The player fires cues, nothing happens in ResolumeResolume's OSC Input is off (Preferences → OSC). The Resolume status dot and preflight.py say so. Keep OSC Output off, or on another port: sending to its own input makes a feedback loop.
The player sits at one barAbletonOSC isn't enabled as a Control Surface, or Live isn't playing.
Follow Live says no player runningThe timeline mirrors cue_player, not Live directly. Test.command starts it; on its own: python3 cue_player.py --follow --preview. Ableton Link has nothing to do with it — Link shares tempo, not the playhead's position.
Follow Live says Live · stoppedAll connected; Live just isn't playing. Press play.
Follow Live says Live not reachableThe player is running but Live isn't answering: Live is closed, restarting, or AbletonOSC is off. The player keeps asking every two seconds and reconnects by itself when Live is back.
Live's tempo changed by itselfAbleton Link is on and another app in the session (Arena, TouchDesigner) has a different tempo. Link makes everyone agree, so Live follows. Set the tempo in Live, or turn Link off in the others.
A stray player won't stopEither launcher stops leftovers when it starts. By hand: pkill -f cue_player.py.
The previz is darkNothing is sending. Design a look, or press Chase in Blender's Venue tab.

Why both Blender and the browser

The 3D view under the floor plan is a map: it answers where a par points and what it covers, while you drag. Blender is a photograph: haze, beam scattering, the screen lighting your face, soft shadows, and renders you can show someone. Rebuilding that in the browser would be weeks of shader work for a worse answer, so each stays where it is good.
